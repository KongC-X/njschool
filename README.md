### 命名规范

| 规则 | 说明 |
|---|---|
| 学校文件名 | **学校全称.md**，不带区名后缀（区由上级目录承载） |
| 完全中学的归属 | 如南外（含初中部 + 高中部），归入**高中学段**目录，一份档案同时覆盖两个学部并在文首标注 |
| 校区分校 | 同一办学主体多校区 → **一份档案**（如南师附中三校区）；独立办学主体（如金中仙林分校）→ **独立档案** |

## 格式设计：Markdown 作内容层

### 为什么是 Markdown

学校信息有三端需求：**人读、程序读、App 渲染**。Markdown 同时满足：

| 需求 | 满足方式 |
|---|---|
| 人读 | 任意编辑器、GitHub、Obsidian 直接看 |
| 程序读 | 标题层级规整，可脚本解析 |
| App 渲染 | 小程序 / Web 均有成熟的 md 渲染库 |

所以**现在写的 md 不会浪费**——它就是未来 App 的内容源，不需要重写。

### 三层分工

| 层 | 载体 | 作用 |
|---|---|---|
| 内容层 | 每校一个 `.md` | 承载全部档案正文 |
| 索引层 | `index.json` | 学校名 / 区 / 学段 / 类型 / 梯队 / 文件路径 / 一句话定位 |
| 展示层 | 本地 md → 未来的 App | App 读 `index.json` 做列表与搜索，点击后渲染对应 md |

### 为什么现在是静态文件而不是数据库

学校信息更新频率低（每年 5 月政策一变），静态文件 + 索引的成本最低。等内容稳定后再灌进云数据库（小程序云开发 / Supabase）也就是一个脚本的事。

**建议的演进路径**：

1. **现在**：静态 md + index.json，本地查看
2. **下一步**：写一个 30 行的静态页面，读 index.json 渲染列表 + 加载 md 正文，部署成网站
3. **之后**：内容灌入云数据库，前端加收藏、对比、筛选等交互；小程序版复用同一份数据

## 档案结构模板

### 小学（十段式）

1. 学校速览（关键信息表，带信度标注）
2. 基本情况（创办背景 / 集团架构与校区 / 办学规模 / 校园环境）
3. 办学特色（理念 / 特色课程 / 社团项目 / 体育指标 / 国际理解 / 双减）
4. 师资力量（数据表 + 客观提示）
5. 招生与施教区（各校区范围 / 招生方式 / 时间节点 / 入学条件）
6. 升学表现（对口初中 / 小升初通道 / 对口校中考表现）
7. 荣誉与认证
8. 家长口碑与评价
9. 择校视角小结
10. 数据来源与可信度（含**数据缺口清单**）

### 初中（十一节，含「年级与班级」专节）

1. 学校速览
2. 基本情况
3. **年级与班级** ← 班级数、三年变化、校区分布、均衡分班
4. 招生入学（施教区 / 摇号 / 政策调整 / 时间轴）
5. 升学政策（指标生 / 特长生 / 中考路径）
6. 升学表现（中考成绩逐年、四星率、六大率、高分段）
7. 师资与办学特色
8. 学费与就读成本（民办）
9. 家长口碑与评价
10. 择校小结
11. 数据来源与可信度（含数据缺口清单）

### 高中（十一节，含「班型与分班」「升学政策」专节）

1. 学校速览
2. 基本情况
3. **班型与分班** ← 班型体系、班号分布、分班依据、动态调整规则
4. 招生与录取（招生计划 / 投档线逐年 / 特长生 / 报名条件）
5. **升学政策**（指标生 / 综评 / 强基 / 竞赛保送 / 少年班）
6. 升学表现（高考成绩 / 南大录取 / 强基综评 / 高分段）
7. 师资力量
8. 办学特色
9. 家长口碑与评价
10. 择校小结
11. 数据来源与可信度（含数据缺口清单）

## 信度标注体系

全文使用行内标注，与汇总报告的分级一致：

| 标注 | 含义 | 来源举例 |
|---|---|---|
| `[A]` | 官方发布，可直接引用 | 市教育局、市招考院、区政府/区教育局官网、学校官网 |
| `[B]` | 权威媒体转述或官方口径二次汇总 | 南京日报、扬子晚报、人民网江苏、中国江苏网、本地宝 |
| `[C]` | 自媒体 / 家长圈口径，**需交叉验证** | 今日头条、微信公众号、培训机构站点 |

**每份档案末尾都有「数据缺口清单」**，明确列出未获取到的数据及原因，避免以臆造数据填充。

### 核查方法（踩过的坑）

1. **判据优先级**：官方公告/招生简章明文写出的网址 > 官网自身标题即校名 > 搜索结果显示域名页面标题即校名 > 仅第三方转述（**一律不收录**）。
2. **平台槽位命名规律**：鼓楼 `*.njgljy.com`、秦淮 `*.njqhjy.net`、雨花台 `*.yhjyxx.cn`、栖霞 `*.site.qxteacher.com`、江北 `*.njnaedu.cn`、建邺 `www.jyjsfz.cn/<学校代码>/`、高淳 `*.gcjy.info`、江宁 `*.jnjy.net.cn`。槽位名 = **该校历史域名主干（必要时加区域前缀）**，不是拼音规则。
3. **判「无」的举证责任重于判「有」**：曾出现「按拼音猜 4 个子域均不存在 → 判无官网」的错误（实际槽位为 `njycxx`）。因此 null 项须说明已尝试范围，`merge_websites.py` 会单列「缺穷举证据」条目供二次核查。
4. **缩写撞车风险**：`njwlc.cn` 为吴良材眼镜（非五老村小学）、`njdjqxx.com` 实为**南师附中丁家庄初中**（非丁家桥小学）。故 200 + 标题相似不足以定论，须正文校级关键词核对。
5. **状态码双向失效**：假 502（站点实际存活、间歇性报错）与真 200（域名被抢注后正常响应）同时存在，不能只看状态码。
6. **不可用代理隧道失败判死**：构建期探测未响应的站点保留链接并标注「核验时未响应」，不删除。

### 已知未解决

- **南京多区教育平台域名休眠内存**：`28` 所归类为「源站下线」，其中雨花台 `*.yhjyxx.cn` 为**整片平台停机**（8 所），恢复后需批量复活。
- **20 条判空尚缺穷举证据**：不代表结论错误，但建议定期复探，尤其是 `jxjy.info`、`njlsedu.cn` 等整站 502 的区平台。

## 网站（site/）

纯静态站，零框架零运行时依赖。

### 构建命令

```bash
make              # 查看全部命令
make validate     # 仅校验数据（不写文件）
make check        # 语法检查 + 数据校验
make all          # 完整构建：索引 → 站点 → 导出件
make site         # 仅站点（自动先建索引，含产物检查）
make preview      # 本地预览 http://127.0.0.1:8788
```

部署时注入站点基址，sitemap 与 canonical 才会生成（协议要求绝对地址）：

```bash
make site BASE=https://你的域名
```

不设 `BASE` 时**不生成 sitemap**——宁可不产出，也不产出带占位符的无效文件。

### 构建流水线

```
① 读取内容 → ② 校验数据 → ③ 渲染页面 → ④ 写入站点 → ⑤ 检查产物
```

- **② 校验失败即中断**：必填字段、枚举值、URL 格式、档案数量一致性、档案须含「数据缺口」章节。
  校验不通过时**不产生任何文件改动**，避免半成品覆盖线上。
- **⑤ 产物检查**：每页恰好 1 个 H1、lang/canonical/description、样式必须外链、
  内部链接可达、体积预算、sitemap 条目数与页面数一致且无双重编码。
- 任一步失败，命令以非 0 退出，CI 据其中断发布。

页面（211 个）：首页 / 学校库（多关键词+筛选+命中高亮）/ 对比（自选 2–4 所并排）/ 政策与更名 /
数据说明 / 更新日志 / 404 / 204 个详情页（含章节目录）；浅深色自适应 + 手动切换，移动端适配。

### 错误页

`404.html` 使用**从站点根算起**的绝对路径——它会在任意深层路径下被返回，
相对路径会解析到那个不存在的目录，导致样式与链接全部失效。
同时标注 `noindex`，不进 sitemap。

### 发布前人工检查（自动化补不上的部分）

构建检查能覆盖结构、链接、体积、令牌纪律，但**布局是否真的适配窄屏必须实机看**。
每次改动样式后，用浏览器开发者工具切到 **375×812（iPhone SE/8 尺寸）** 逐项确认：

| 检查项 | 判断标准 |
|---|---|
| 整页横向滚动 | `document.documentElement.scrollWidth <= window.innerWidth`（控制台执行） |
| 详情页正文表格 | 应变成「字段名 + 值」的卡片，不应出现横向拖动条 |
| 信度徽章 | 应是窄小的彩色方块，不应被拉伸成整条色带 |
| 目录 | 横向可滑动的单行，不换行、不遮挡内容 |
| 学校库 | 筛选项收在「筛选条件」按钮内，展开后不溢出 |
| 导航 | 品牌名与三个链接不换行、不重叠 |

`scrollWidth` 超标是整页溢出的直接信号，优先查是否有 `min-width` 未在移动断点覆盖。

## 维护方式

新增一所学校：

1. 在 `学段/行政区/` 下创建 `学校全称.md`，按对应学段的模板填写
2. 在 `src/build_index.py` 的 `SCHOOLS` 列表追加一条元组
3. 运行 `python3 src/build_index.py` 重新生成 `index.json`

更新汇总报告（HTML / Excel / 汇总 Markdown）：

```bash
python3 src/build_html.py     # 重新生成 HTML
python3 src/build_md.py       # 重新生成 Markdown 汇总
python3 src/build_csv.py      # 重新导出 CSV
python3 src/build_index.py    # 重新生成索引
```

Excel 需重新构建时，运行 `.南京学校对比表.ref/build.py`。
