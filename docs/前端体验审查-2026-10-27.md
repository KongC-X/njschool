# 前端体验审查报告

> 审查日期：2026-10-27
> 范围：已构建站点 553 页，重点前端展示（文案 / 交互 / UI）
> 方法：真浏览器实测（Chromium 1440×1000 与 390×780）+ 逐页截图 + WCAG 对比度计算 + DOM 度量

## 0. 总体判断

**基础质量比预期好，问题不在"做坏了"，而在"没说完"和"没排好"。**

先列实测通过的项，避免把力气花在没问题的地方：

| 检查项 | 结果 |
|---|---|
| 文本对比度（12 组核心配色） | **11 组达标 AA**，1 组严重不达标（见 A1） |
| 横向溢出（9 页 × 两档宽度） | 全部无溢出 |
| JS 报错 | 0 |
| 卡片等高对齐 | 8 张卡片高度全部 236px，底部链接同一基线 |
| 触控区 | 筛选项 40/44px 达标；导航 39px、面包屑 24px 属临界但可接受 |
| 字号体系 | 1280/1600/1700 三档响应式放大，标度自洽；无写死的游离字号 |

**两个真问题集中在：**
1. **一处的对比度是致命的**——对比表的「—」几乎不可见（1.44:1），而那是「本站未收录」的唯一视觉表达。
2. **文案里有明显的"半句话"**——孤字成行、冗余计数、用词不统一，都是低成本的观感伤。

问题共 **19 项**：立刻改 7 项、值得改 8 项、打磨 4 项。

## 2. 文字描述

### A3 对比页说明文字孤行

- **位置**：`templates/compare.html` 第一个 `p.page-sub`
- **现状**：桌面 1440 下断成两行，第二行只有「会保存在本机，可复制链接分享。」；手机 390 下断成四行，末行只剩「分享。」两个字。
- **问题**：中文排版的孤字（widow）会让人本能觉得"没排完"。这段文案本身也有三件事挤在一起：怎么用、差异怎么看、数据存哪。
- **建议**：拆成一句主说明 + 一行次要说明。「选 2–4 所并排看，只标「不同」不标「更好」」为主句；「选择保存在本机，可复制链接分享」降为 `--muted` 的次行。同时给 `.page-sub` 加 `max-width:46ch`。

### A4 「匹配 545 所 / 共 545 所」

- **位置**：`assets/schools.js` `render()` 里 `cnt.textContent` 的拼装
- **现状**：没有任何筛选时显示「匹配 545 所 / 共 545 所」。
- **问题**：两个数字相同，第一个词「匹配」在无筛选时是无意义的。
- **建议**：无筛选时只显示「共 545 所」；有筛选/关键词时才用「匹配 N 所 / 共 545 所」。三行改动。

### A5 三个「全部」不统一

- **位置**：`assets/schools.js` 三处 `chips(...)` 的 `allLabel`
- **现状**：「全部学段」「全部区」「**不限**性质」。
- **问题**：同一组筛选，第三个换了句式。用户扫读时会把「不限性质」当成另一类控件。
- **建议**：统一成「全部学段 / 全部区 / 全部性质」。

### A6 页脚重复表达

- **位置**：`templates/base.html` 页脚第一列
- **现状**：「公开信息汇编 · 数据版本 v2026-10 · 更新 2026-10-27」。
- **问题**：版本号本身就是年月，「更新」又在同一个月，两个日期并排等于说了两遍。
- **建议**：只留一个：「数据版本 2026-10 · 更新于 10-27」。

### B2 学段卡片副标题跑题

- **位置**：`src/pipeline/render.py` `home()` 里 `config.LEVEL_DESC[lv].split("，")[0]`
- **现状**：三张卡片副标题分别是「小学阶段无官方升学率指标」「初中中考成绩多数无官方公示」「高中以 2026 年投档线为核心参照」。
- **问题**：前两句是"为什么没有数据"，属于免责说明，不是用户点进去前想知道的。卡片标题已经写了「小学 340 所」，副标题却转去讲数据局限。
- **建议**：副标题改成「能查到什么」，例如「施教区 · 招生计划 · 对口初中」。免责说明保留在 about 页与页脚即可——那里已经写了。

### B3 对比分组名抽象

- **位置**：`assets/compare.js` `const GROUPS = { identity:'身份', path:'通路', evidence:'证据' }`
- **现状**：三组分别叫「身份 6 项 / 通路 4 项 / 证据 3 项」。
- **问题**：
  - 「身份」「通路」是内部模型词，家长不会这么说；
  - **「证据」组里放的是「办学规模 / 校址 / 一句话定位」**，这三项跟"证据"没有关系，名实不符。
- **建议**：改成「基本信息 / 入学相关 / 其他」，或干脆去掉组名只留分隔。第 3 组若保留，叫「补充信息」。

### C7 手机端 placeholder 截断

- **位置**：`templates/compare.html` `#pick` 的 placeholder
- **现状**：手机上显示到「（如「琅琊路」「金中」「打」」——截在引号中间。
- **问题**：看起来像内容出错。
- **建议**：缩短为「输入校名，如「琅琊路」」。

## 3. 交互体验

### B5 差异标记在最常见的场景下失效

- **位置**：`assets/compare-core.js` `buildRows()` 的 `isDiff` 逻辑 + `assets/pages.css` `.cmp-row.has-diff > .cmp-rowhead::before`
- **现状**：只有"行内独一无二"的格子才加琥珀底。**2 比 2 的时候没有任何格子是独一无二的**，于是整行只剩行首一条 3px 竖线。
- **实测**：四所小学对比，「行政区」是 玄武区×2 + 鼓楼区×2，行被判定为差异行，但 4 个格子全部无标记。
- **问题**：这个站点 90% 的对比都是 2 比 2（两所公办 vs 两所民办、两个区对比），恰好在最主流的场景下最弱。
- **建议**：保留"独一无二"的强标记，另加弱标记——行内只要不是全部相同，所有参与比较的格子加 `--amber-bg` 的 30% 淡底（或只给行首竖线加粗到 4px 并与格子间加内阴影）。核心是让"这一行不同"在行内可感知，而不是只靠左边缘。

### B6 「清空」和已选项长得一样

- **位置**：`assets/schools.js` `resetAll` 相关 / `assets/compare.js` `#clearInline`
- **现状**：`<button class="chip">清空</button>` 与已选中的 `<button class="chip on">某某小学 ×</button>` 同一组件，只差一个 `on` 类。
- **问题**：白底 + 灰边在蓝色选中项之间很扎眼，且形状一致，容易被当成"还有一个已选项"。
- **建议**：清空改成纯文字按钮（下划线或 `--muted` 小字），或加 `×` 图标与分隔线隔开。

### B8 手机端导航拥挤

- **位置**：`assets/site.css` `.nav` / `assets/responsive.css` ≤420px 段
- **现状**：390px 下品牌只剩一个「宁」字方块，右侧 5 个链接「首页 学校库 对比 政策 数据说明」+ 主题按钮排成一行，链接高度约 30px。
- **问题**：5 项中文在 390px 里几乎贴在一起，分组关系消失；30px 的高度低于 44px 触控下限。且「宁」字方块失去站名，新用户不知道这是什么站。
- **建议**：≤420px 收成「汉堡菜单 + 站名」；或至少保留「学校库 / 对比」两项，其余收进「更多」。品牌保留「南京档案」四字而非单字。

### B9 首屏没有骨架屏

- **位置**：`templates/schools.html` `<div class="grid" id="grid"></div>`
- **现状**：`schools-data.js` 153.8 KB（gzip 40 KB）下载并解析完之前，`#grid` 是空的；计数行也是空的。
- **问题**：慢网下用户看到的是「标题 + 一排筛选 + 大片空白」，很像页面坏了。
- **建议**：初始 HTML 里放 6 个灰块占位（纯 CSS，无需 JS），数据到位后整体替换。成本很低，观感改善明显。

### C3 「0/4」空行占高度

- **位置**：`assets/compare.js` `is-blank` 行
- **现状**：四所小学对比里「2026 招生计划 0/4」「学费 0/4」「办学规模 0/4」三行，整行只有横线或「未获取」。
- **问题**：诚实是必要的，但三整行的空白稀释了有内容的行。
- **建议**：把连续的空值行合并为一行摘要：「招生计划 / 学费 / 办学规模 —— 四所均未收录」，点开展开。既保留诚实，又不占三行。

## 4. UI 设计

### A1「—」对比度 1.44:1（本次最该修的一条）

- **位置**：`assets/pages.css:267` `.cmp-cell.is-na{color:var(--line-strong)}`
- **实测**：文字色 `rgb(211,215,227)`，白底对比度 **1.44:1**。WCAG AA 正文要求 4.5:1。
- **问题**：`--line-strong` 是**边框色**，被借来当文字色。「—」是对比表里"本站未收录"的唯一视觉表达，等于看不见。四所小学对比里有 **44 个格子**是这种状态。
- **建议**：改用 `var(--muted)`（5.39:1，达标）。「—」本身是短横线，视觉权重天然很低，不需要再压颜色。若要保留"更淡"的感觉，用 `opacity` 会让对比度同步下降，不可取——改小字号（`--f-2xs`）比改浅色更安全。

### A2 首页副标题孤字成行

- **位置**：`assets/pages.css:20` `.hero p{max-width:64ch}`
- **实测**：段落宽 685px、正文 54 字、折 2 行；第二行只剩「「未获取」。」约 6 字。
- **问题**：首屏第一段就出现孤行，观感直接掉一档。
- **建议**：`max-width` 收到 `46ch`（约 34 汉字/行）让两行更均衡；或把文案缩到 40 字以内让它一行放下。

### A7 目录项换行破坏节奏

- **位置**：`src/pipeline/mdtext.py` `_build_toc()`（用原始 h2 名）
- **实测**：目录 10 项，9 项高 30px，第 8 项高 **51px**——因为标题是「八、家长口碑与评价（[C]，需自行甄别）」。
- **问题**：目录靠等距列表建立节奏，一项变两行会让后面所有项视觉上错位。
- **建议**：目录里去掉括号注释（`（[C]，需自行甄别）`），正文标题保留。或在 `_build_toc` 里对超过 N 字的标题做截断 + `title` 属性。

### B1 详情页首屏信息重复

- **位置**：`templates/detail.html` 页头徽章 vs 正文「一、学校速览」表
- **现状**：页头已有 `小学 / 公办 / 鼓楼区 / 琅小` 四个徽章 + h1 校名；紧接着正文速览表 5 行是「学校全称 / 简称 / 所在区 / 办学性质 / 学校类别」。
- **问题**：5 行里 4 行与页头重复（只是"所在区"带了片区补充、"学校类别"带了学制）。用户滚过一屏才发现"这些我已经看过了"。
- **建议**：速览表只保留增量信息（所在区片区、学校类别与学制、集团归属等），把全称/简称/性质交给页头；或把速览表整体折叠（`<details>`），默认收起。

### B4 正文行宽 65 汉字

- **位置**：`assets/pages.css:124` `.article`（无 `max-width` 限制段落）
- **实测**：`.article > p` 宽 **1035px**、字号 16px → **每行 65 汉字**。中文舒适区间是 30–40 汉字。
- **问题**：长档案（最大 92 KB）里，视线从行尾回到行首的成本很高，读三行就串行。
- **建议**：`.article > p, .article > ul, .article > ol, .article > blockquote { max-width: 34em }`（约 36 汉字）。表格与代码块保持全宽即可。

### B7 404 页入口卡 3+1 落单

- **位置**：`assets/pages.css:365` `.nf-links{grid-template-columns:repeat(auto-fill,minmax(210px,1fr))}`
- **现状**：容器 720px 宽，210px 最小宽算出 3 列，4 个入口排成 3+1，第 4 个「数据说明」孤零零占第二行左端。
- **问题**：看起来像少了一个入口。
- **建议**：`minmax(300px,1fr)` → 自动变 2 列 2×2，四个入口对称；或补第 5 个入口「全部学校索引」凑成 3+2。前者更好。

### C1 / C2 目录的两处细节

- **C1**：`assets/pages.css:115` `.toc-title{text-transform:uppercase}` —— 「本页目录」是纯中文，`uppercase` 不产生任何效果，是从英文模板沿用的死规则，建议删掉。
- **C2**：`assets/pages.css:117` `.toc li a{padding:5px 12px;line-height:1.5}` —— 10 项目录行高偏紧，与正文 1.75 的行高不搭。建议 `padding:7px 12px`。

### C4 唯一用强调色的数字

- **位置**：`assets/pages.css:42` `.stat:first-child b{color:var(--accent)}`
- **问题**：`tokens.css` 开头明确写着「强调色只用于可交互元素与当前状态」。首页第一格「545 所」用 accent 蓝，但它不可点、也不是当前状态。同类元素（其余 4 格）用 `--ink`，造成"第一格可点"的错觉。
- **建议**：统一用 `--ink`，靠字号（`calc(--f-2xl * 1.45)`）建立层级就够了。

### C5 响应式断点分散重复

- **实测**：`responsive.css` 共 12 个 `@media` 块，其中 `(max-width:720px)` 出现 **3 次**、`(min-width:1280px)` / `(min-width:1700px)` / `(min-width:1600px)` 各 **2 次**。
- **问题**：功能上没有 bug（块内选择器不重复），但同一断点散在三处，调一个断点时极易漏改其中一处——这个项目此前就踩过"重复写入导致层叠错乱"的坑。
- **建议**：按断点归并，一个断点一个块，顺序从大到小。约 30 分钟。

### C6 手机端品牌只剩一个字

- **位置**：`assets/responsive.css` ≤420px 段 `.brand-text{display:none}`
- **问题**：390px 下左上角只剩一个「宁」字方块，与「南京中小学档案」这个站名脱节。
- **建议**：改为缩写字标「南京档案」（4 字，约 52px），仍能在一行内放下。

## 5. 建议实施顺序

**第一批（半小时内，纯文案与 1 行 CSS）**
A1 → A2 → A4 → A5 → A6 → C1 → C7

这批做完，用户能直接感知的变化是：对比表里的「—」看得见了、首页第一段不孤行了、筛选器用词统一了。

**第二批（半天，观感提升最大）**
B4 行宽 → B1 详情页去重 → B7 404 布局 → B2 学段卡片 → B3 分组名

**第三批（1 天，交互与响应式）**
B5 差异标记 → B6 清空按钮 → B9 骨架屏 → B8 手机导航

**第四批（可选）**
A7 目录截断 → C2 目录行距 → C3 空行合并 → C4 统计色 → C5 断点归并 → C6 品牌字标
