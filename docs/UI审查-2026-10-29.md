> 方法：真浏览器度量（1440 / 1280 / 1024 / 768 / 430 / 400 / 390 / 375 / 360 / 350 / 344 / 341 / 340 / 320）+ DOM 采样 + 对比度计算 + 静态扫描 + 人工读码

## 0. 一句话结论

底子是同类站点里少见的扎实——令牌化配色、内容优先、注释里写满「为什么这么定」、核心逻辑有单测（前端 33 个用例 + 数据管道 65 个用例全绿）。问题不在审美取向，而在**四个系统性根因**：

| 根因 | 表现 | 牵连条目 |
|---|---|---|
| **① 没有版心** | `--w-wide:1120px` 定义了 0 处引用，`.wrap` 实测 1350px；窄内容被拉满（分数查学校 1350px 卡里只有 150px 输入框，右侧 850px 空白） | V6、V7、V8、V11 |
| **② 令牌被绕开** | 组件内边距用 3/5/7/9/13/14/18px（标尺是 4/8/12/16…），行高 17 个值，字号 20 档且 4 处在媒体查询里重定义 | V3、V4、V6、V9、V14、E3、E4 |
| **③ 状态没收敛** | 折叠状态写一次就不管、输入即全量重建、非法输入静默回落、空态不说是哪条挡住 | U5、U6、U7、U9、E12 |
| **④ 窄屏是补丁式适配** | 表格缺包裹层、卡片断崖式换列、导航靠缩 padding 硬塞 | U1、U11、U14、U15、V10、V13 |

按影响排序，**上线前必须处理 10 条**（第 5 节 P0），其余可分批。

### 视觉基线建议

1. **一条版心、两种宽度**：`--w-wide`（1240px，全站硬上限，`.wrap` 与 `.nav-in` 同时生效）+ `--w-read:46em`（长文正文）。页面标题、页头卡、正文卡一律以同一左边缘为起点，只有 `.article` 允许缩进一栏。禁止再出现「页头满宽 + 正文居中」（V8）。
2. **字阶只有一个来源，且必须单调**：所有字号在 `:root` 用 `clamp()` 定义，断点内只允许改标题档（`--f-xl` 以上）。任何改动都要跑 375/721/1024/1279/1280 五个宽度，**不许出现「视口变大、字号变小」**。正文下限 16px，说明文字下限 12.5px（V3、V4）。
3. **间距只用 4px 标尺**：组件内边距只允许 8/12/16，块间 40、块内 20、行间 8；`--s-*` 之外不出现裸 px 内边距。唯一例外是 `.nav-links a` 在 ≤480 的 `padding:7px 5px`（见 V9）。
4. **颜色只表达三件事，且打印必须同构**：结构 = `--line`（只做分隔，不做控件边界）；交互 = `--accent` 系 + `--line-control`（≥3:1 描边）；状态 = green/amber/red（只用于信度与截止）。**次要文字不许用 opacity**（V1、V2）。打印侧现在是唯一「一半彩色一半黑白」的硬伤，在 `pages.css:207` 的 `@media print{}` 里加这三行，必须成套出现：
   ```css
   @media print{
     :root{--green:#000;--red:#000;--amber:#000;--green-bg:#fff;--red-bg:#fff;--amber-bg:#fff;--mark-bg:#e6e6e6}
     .b,.conf{border:1px solid #000}
     .roads mark,.sk-hit{background:var(--mark-bg);color:#000;border:1px solid #000}
   }
   ```
   第一行把语义色归零、第二行用边框替代底色承载「公办/民办/信度」的区分、第三行保住施教区自查命中高亮——否则 `mark` 变纯黑字，命中信息在纸上彻底丢失。`--mark-bg` 需同步在 `tokens.css:19` 附近声明，避免硬编码色值被 check 脚本判违规。实测依据：print 媒体下 `.b-pub` 仍是 rgb(17,100,58) on rgb(232,247,238)、`.b-pri` 仍是 rgb(156,28,18) on rgb(253,236,235)，而 `.b-lv` 已变纯黑白。
5. **层级靠字号差，不靠数字**：h1 40 > 段落标题 30 > 数字 22–34.5 > 正文 16，**数字永远不超过所在页的 h1**（V12、V13）。
6. **同一语义只有一套组件视觉**：可点卡片 2 套内边距、2 种 hover；胶囊/按钮内边距只 8/12；跨页的同一元素（页面标题、内容卡、统计数字）同宽同字号（V9、V14、V15）。
7. **移动端硬约束：不允许单字孤行**。三格/两列这类等分容器，先保证标签单行（改字号、缩文案或改列数），再谈视觉权重；验收指标是「任一行文本行宽 ≥ 2 个汉字」（V10、V13 两处孤字行宽分别只有 7.8px / 14.3px）。

### 三处必须在上线前处理

1. **E15（压缩 + 缓存头）**——唯一「改部署配置就拿 −64%」的项，覆盖 546 页 × 所有回访；它不修，后面所有代码优化的绝对收益都会被「未压缩 + 每次重新校验 6 个文件」吃掉。工作量约 1 小时，零代码风险。
2. **E12（逐字重建 545 卡）**——学校库是主入口。本机 59.2ms/键，移动端按 CPU 差 4–6× 推算 250–350ms，属「用了会卡」的量级；修法只落在 schools.js 一个文件、30 行以内，不动组件结构，回归面极小。
3. **E5（721–1279px 字号最小）**——目标用户 35–45 岁家长，iPad 横屏 / 13″ 笔记本恰好是主阅读尺寸，而这一段是全站最小字号（15 / 13.5px），比 375 手机还小。3 行令牌修复，回归面只有字号。

**不选 E1/E2 的理由**：拆 CSS 必须先做组件归属重构（E2），改完要回归 546 页 × 6 个断点，工时与风险都超出「上线前」。另外 **gzip 不会让 E1 的边际变小**——21,068 B 未压缩占 27.5%，gzip 后 7,840 B 占 27,233 B 的 28.8%，比例不变；E1 的真正价值不只是字节，而是让 515 条规则里那 150 条「所有站级页 0 命中」的规则不再进入关键路径。建议排在上线后第一个迭代，与 E2 一起做。

### 工程侧不做的事

1. **不把 545 页改成 SPA / 引入 Next、Vite**：当前 546 页静态产物实测 FCP 首页 48ms、详情页 96ms，DCL 19/56ms，all.html 是零 JS 的爬虫入口。换成框架等于用 200–500KB 运行时换一个更慢的首屏，还丢掉「py 构建 + 手写 CSS + 零 node 依赖」这个优势。唯一真痛点是 E12 的 DOM 重建，30 行 JS 解决。
2. **不引入 Tailwind / CSS-in-JS / 全量 purge**：92KB 手写 CSS 有令牌层、0 处硬编码色值、0 处非令牌字号——比多数设计系统干净；浪费的是 **21KB 死文件（E1）**，拆文件即可回收。
3. **不做全站 prefetch 或大列表虚拟滚动**：prefetch 545 个详情页会瞬间打满 23MB 带宽，而站内平均跳转深度只有 1–2 层；只给「接着看」的 4 张卡加 `rel=prefetch`（3 行）即可。虚拟滚动会把滚动锚点、焦点、搜索高亮、打印全部复杂化——筛选后通常 ≤60 条，E12 的「上限 60 + 分批 append」已经够用。
