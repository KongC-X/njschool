# 数据补全与来源标注 · 改进方案

> 编制：2026-10-23　|　对象：204 份学校档案　|　配套盘点：`data/data_audit.json`、`data/missing_candidates.csv`

---

## 摘要（先给结论）

1. **收录不全不是个别遗漏，而是系统性的**：栖霞区只收了 8 所小学、5 所初中，缺整个西岗/摄山片区（已核实官方校名：**南京市栖霞区摄山星城小学**、**南京市栖霞区摄山初级中学**），另有马群、尧化等片区未覆盖。根因是从未与官方招生计划做过「应收/实收」对账。
2. **升学数据不可能"补全"**——南京官方不公布学校层面的中考升学率。正确做法不是继续找数字，而是**改用可核验的替代指标**，并把家长圈数字明确标注口径。
3. **特长生数据最适合优先做**：它是唯一同时满足「官方公开发布」「结构清晰」「与 C++ 信奥业务直接相关」三个条件的数据集。
4. 建议顺序：**对账补录（1 周）→ 特长生专项（1–2 周）→ 来源补齐与口径规范（穿插）→ 升学替代指标（2 周）**。

## 一、问题归类

用户提出的四类问题，本质是四个不同层面的缺陷，处理方式完全不同：

| 层面 | 问题 | 本质 | 处理方式 |
|---|---|---|---|
| **覆盖** | 学校没收录（摄山星城等） | 缺少权威基线，无法判断"应收多少" | 与官方招生计划对账 |
| **准确** | 部分信息不准确 | 缺少交叉验证与版本管理 | 双源比对 + 变更留痕 |
| **可追溯** | 校内数据缺来源与明细 | 数据与来源未绑定 | 每条值必须挂来源与时点 |
| **期望数据** | 升学率、特长生计划缺失 | 有些数据根本不存在公开版本 | 换指标 / 换获取渠道 |

关键认知：**前三个是工程问题（能修），第四个是信息可得性问题（要换思路）**。

## 三、改进思路（五个机制）

### 机制 1：建立「应收 / 实收」对账

**这是解决收录不全的唯一可靠办法**，靠交叉引用只能碰运气。

- **基线来源**：每年 5–6 月，各区教育局发布《义务教育招生入学工作实施方案》及其附件（施教区一览、公办小学/初中招生计划、民办派位计划）。附件里通常逐校列出**校名 + 招生班级数**，这就是权威的"应收名单"。
- **做法**：按区分年抓取附件 → 生成 `expected_schools.csv`（区、学段、校名、班级数、来源、日期）→ 与库内档案做差集 → 输出缺口清单。
- **产出**：`数据缺口清单` 与「覆盖看板」，每区显示「应收 N / 实收 M / 缺 K」。
- **注意**：新建校、更名校、校区拆分会导致名单波动，差异需人工确认后入库，不做自动创建。

### 机制 2：数据四要素（值 / 口径 / 来源 / 时点）

当前档案的痛点是「数字有，但说不清是哪来的、哪一年的、什么口径」。建议把每条可量化数据统一为四要素：

| 要素 | 示例 |
|---|---|
| 值 | 四星高中达线率 82% |
| 口径 | 普通高中一批次（四星）上线率，不含国际班 |
| 来源 | 学校 2026 届中考喜报（公众号，2026-07-12） |
| 时点 | 2026 届 / 采集于 2026-10-17 |

**落地方式**（不推翻现有档案结构）：

1. 在 `index.json` 所依赖的档案里，为「学校速览」类表格增加一列**来源编号**，正文末的「数据来源」表按编号索引（已有该表，只需补编号）。
2. `pipeline/schema.py` 增加字段校验：出现百分比/人数类数值时，若同段落无 `[A]/[B]/[C]` 或来源编号，则**构建告警**（不是阻断，避免大量存量报错）。
3. 对 102 处无标注的四星率做一次性补齐——这是本次盘点里最高性价比的修复。

### 机制 3：缺失值三档规范（禁止估算）

现行「数据缺口」把「查不到」和「官方没公布」混在一起，维护时无法区分成本。建议分三档：

| 档位 | 含义 | 展示措辞 | 后续动作 |
|---|---|---|---|
| `not_published` | 官方明确不公布（如中考升学率） | 「官方未公布」 | 不再重复检索，改用替代指标 |
| `not_found` | 应公布但未检索到 | 「未获取」 | 进入待补清单，定期复探 |
| `not_applicable` | 该项对该校不适用（如小学无投档线） | 留空或「—」 | 不进入统计 |

这一档位可以直接落到 schema 里（`gap_type`），并在站点「数据说明」页公开规则。

### 机制 4：特长生专项（业务优先）

这是唯一「官方每年公开发布 + 结构化 + 与 C++ 信奥业务直接相关」的数据集，建议单独建库，而不是散落在各校档案里。

**字段设计**

| 字段 | 说明 |
|---|---|
| 学段 / 学校 / 区 | 关联既有档案 |
| 类别 | 科技（含信息学）、体育、艺术 |
| 项目 | 如「信息学」「机器人」「女子足球」 |
| 计划人数 | 招生计划表原文数值 |
| 招生范围 | 全市 / 本区 / 集团内 |
| 报名条件 | 如「CSP-J/S 二等奖以上」「市级竞赛获奖」 |
| 测试方式 | 加试科目、形式 |
| 时间节点 | 简章发布、报名截止、加试日期 |
| 来源 | 市教育局特长生文件 / 学校简章 URL |

**为什么优先**：家长问「学编程能不能进这所初中/高中」，现在只能靠翻 204 份档案里的零散段落；有了这张表就能直接回答，而且能反哺课程顾问的判断（哪些学校认 CSP 证书、什么时间点报名）。

**范围建议**：先做**科技/信息学类**（数据量小、业务价值最高），再补体育与艺术。当前 38 所档案提到科技/信息学，可作为第一批核查对象。

### 机制 5：升学数据改用替代指标

**先纠正一个预期**：南京官方不公布学校层面的中考升学率与「小升初升学率」。小学阶段根本没有"升学率"这个概念（对口直升或派位）。因此继续找"升学率"只会得到家长圈数字，无法标注为 `[A]`。

建议按学段换成**可核验的替代指标**：

| 学段 | 不可得 | 可用的替代指标（均为官方或可核验） |
|---|---|---|
| 小学 | 升学率 | 对口初中（施教区/直升）· 电脑派位计划与报名人数 · 对口初中的中考表现（作为间接参考，需注明非本校出口） |
| 初中 | 中考升学率（无官方） | **指标生名额与分配**（官方）· 特长生录取人数（官方）· 四星高中达线率（家长圈 `[C]`，标注口径）· 学校喜报原文（`[B]`，注明"校方自述"） |
| 高中 | — | **投档线与位次（官方）**· 招生计划与班型（官方）· 学科/科技特长生计划（官方） |

同时把「升学表现」章节的写法标准化：**先给官方指标，再给家长圈数据并标注「仅供参考」**，两者不混排。

## 四、优先级与迭代路径

排序依据：**业务价值 × 可获取性 ÷ 成本**。特长生虽业务价值最高，但依赖对账后的准确校名，故排在补录之后。

### P0（约 5 人日）· 止血

| 任务 | 交付物 | 验收 |
|---|---|---|
| 栖霞区补录（摄山星城小学、摄山初级中学等） | 新增档案 3–5 份 | 与区政府/区教育局公示一致，含信度与来源 |
| 全库对账（至少鼓楼、玄武、秦淮、建邺、栖霞、雨花台 6 区） | `data/expected_schools.csv` + 缺口清单 | 每区「应收/实收」数字可复核 |
| 102 处四星率补信度与来源 | 档案定点修改 | 构建检查：百分比数值同行必须有 `[A]/[B]/[C]` |
| schema 增加 `gap_type` 三档 | `pipeline/schema.py` | 校验通过，站点「数据说明」同步 |

## 五、质量门禁（让"补全"不会退化）

1. **构建阻断**：百分比/人数类数值缺信度标注 → error（存量先降级为 warning，修完再提升）
2. **来源必填**：新增条目若无来源 URL 或文件编号，schema 拒绝
3. **口径字段**：任何比率数据必须同时有「分子分母定义」，否则视为无效
4. **禁止估算**：构建脚本扫描「约」「大约」「估计」+ 数字的组合，命中即告警
5. **变更留痕**：数据修正走 `changelog.md`，重大口径调整单独记录

## 六、风险与取舍

| 风险 | 说明 | 应对 |
|---|---|---|
| 对账基线拿到不全 | 部分区不公开逐校班级数 | 退化为「区教育局公布的学校名录」+ 民办派位名单拼合 |
| 特长生政策逐年变 | 项目、人数、条件每年调整 | 按年份存快照，不做跨年覆盖 |
| 升学数据被误读 | 家长圈数字被当成事实 | 页面固定标注口径与信度，禁止在榜单中出现 `[C]` 数据 |
| 补录引发连锁修改 | 新增学校会影响对口关系、区统计 | 补录后重跑对账与统计，不手工改汇总 |
| 工作量被低估 | 206→约 260 所，每份 4500 字 | 按区批量推进，每区完成即验收，不做大爆炸式补录 |
